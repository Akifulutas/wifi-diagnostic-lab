# Data Dictionary — Wi-Fi Diagnostic Lab

Version: 1.0.0 (October 2026)

This document formally specifies all data fields, units, collection sources, and missing-value semantics across raw manifests and processed tables.

---

## 1. Run Manifest (`manifest.json`)

Stored in each individual run directory under `data/raw/<study>/<run_id>/manifest.json`.

| Field | Type | Unit | Description |
|---|---|---|---|
| `schema_version` | String | - | Version of the manifest schema (e.g. `"1.0.0"`). |
| `run_id` | String | - | Unique identifier formatted as `<position>_<direction>_rep<index>_<timestamp>`. |
| `timestamp_utc` | String | ISO 8601 | UTC timestamp of experiment initiation (`YYYY-MM-DDTHH:MM:SSZ`). |
| `day_label` | String | - | Categorical label for measurement day (`"day1"` or `"day2"`). |
| `repetition_index`| Integer | Count | 1-indexed repetition counter within the specific condition. |
| `condition` | Object | - | Configuration object (position, direction, stream count, phase durations). |
| `hardware` | Object | - | Hardware profile (MacBook Pro M1 Pro, FRITZ!Box 7530 AX, Ethernet server). |
| `outcome` | Enum | - | Execution status: `ok`, `tool_error`, `timeout`, `parse_error`, `condition_changed`. |
| `failure_reason` | String/null| - | Detailed explanation if `outcome != ok`. Retained for failure accounting. |
| `raw_files` | Map | - | Relative file paths to `iperf_raw.json`, `ping_raw.txt`. |

## 2. Processed Run Summary Table (`run_summary.csv`)

Generated by `python -m wifi_lab analyse`. Represents one aggregated row per attempted measurement run.

| Column Name | Type | Unit | Nullable? | Description |
|---|---|---|---|---|
| `run_id` | String | - | No | Unique run identifier. |
| `day_label` | String | - | No | Measurement day category. |
| `position_id` | String | - | No | Position code (`"L1"` = near LOS, `"L2"` = far NLOS). |
| `direction` | String | - | No | Traffic direction (`"download"` or `"upload"`). |
| `repetition` | Integer | Count | No | Repetition sequence number. |
| `outcome` | String | - | No | Run status (`"ok"`, `"tool_error"`, etc.). |
| `receiver_throughput_mbps` | Float | Mbps (decimal, $10^6$ bit/s) | Yes | Throughput delivered at the receiver endpoint during steady-state load. |
| `sender_throughput_mbps` | Float | Mbps | Yes | Throughput observed at the sender endpoint. |
| `tcp_retransmits` | Integer | Count | Yes | TCP segment retransmissions reported by iperf3. |
| `idle_rtt_median_ms` | Float | Milliseconds | Yes | Median ICMP RTT during the 30-second idle baseline phase. |
| `idle_rtt_p95_ms` | Float | Milliseconds | Yes | 95th percentile ICMP RTT during idle baseline. |
| `loaded_rtt_median_ms` | Float | Milliseconds | Yes | Median ICMP RTT during the 60-second active TCP load phase. |
| `loaded_rtt_p95_ms` | Float | Milliseconds | Yes | 95th percentile ICMP RTT during active TCP load. |
| `recovery_rtt_median_ms` | Float | Milliseconds | Yes | Median ICMP RTT during the 30-second recovery phase. |
| `delta_rtt_median_ms` | Float | Milliseconds | Yes | Paired difference: `loaded_rtt_median_ms - idle_rtt_median_ms` (Bufferbloat index). |
| `sent_probes` | Integer | Count | No | Total ICMP echo requests scheduled. |
| `received_probes` | Integer | Count | No | Total ICMP echo replies successfully received. |
| `loss_rate_pct` | Float | Percentage (%) | No | Probe packet loss percentage: $(1 - received/sent) \times 100$. |
| `failure_reason` | String | - | No | Diagnostic error string if run failed (empty string if OK). |

## 3. RTT Sample Table (`rtt_samples.csv`)

One row per scheduled ICMP ping probe across all runs.

| Column Name | Type | Unit | Description |
|---|---|---|---|
| `run_id` | String | - | Parent run identifier. |
| `seq` | Integer | Count | ICMP sequence number. |
| `timestamp_rel_s` | Float | Seconds | Elapsed time from experiment start ($t_0$). |
| `phase` | Enum | - | Active phase: `idle`, `warmup`, `load`, `recovery`, `boundary`. |
| `rtt_ms` | Float | Milliseconds | Round-trip time. Explicitly `null` if probe timed out (never recorded as 0.0 ms). |
| `is_boundary_guarded`| Boolean | - | `true` if probe fell within $\pm 1.0\text{s}$ of a phase transition; excluded from steady-state statistics. |

---

## 4. Key Methodological Rules

1. **Units:** Throughput is strictly decimal Megabits per second ($1\text{ Mbps} = 1,000,000\text{ bits/second}$).
2. **Missing Latency:** A dropped probe is logged with `rtt_ms = null`. Dropped probes contribute to `loss_rate_pct` and are never treated as zero-delay responses.
3. **Phase Boundary Guard:** Probes transmitted within 1.0 second of an `idle` $\rightarrow$ `warmup` or `load` $\rightarrow$ `recovery` transition are marked `boundary` to prevent transient socket teardown or buffer draining from skewing steady-state distributions.
4. **Failure Accounting:** Failed runs remain in `run_summary.csv` with their corresponding `outcome` and `failure_reason`. They are not silently discarded or repeated until a clean number is obtained.
