Evidence-Based Diagnostic Findings (WiSlow Methodology)

Finding 01 Near-AP Throughput Plateau & Wired Ceiling

Observation: At position L1 (1.2m Line-of-Sight), receiver throughput plateaus at 811.9 Mbps, approaching the theoretical payload limit of 1000BASE-T Gigabit Ethernet (~940 Mbps).

Candidate Explanations

  • The Gigabit Ethernet link between FRITZ!Box 7530 AX and the local server acts as the primary throughput bottleneck.
  • The M1 Pro client's 2x2 MIMO 80MHz PHY ceiling (~1200 Mbps) is constrained by 802.11ax MAC overhead and contention.
  • Endpoint CPU / socket buffer sizing capping single-stream TCP performance.

Missing Evidence

  • Wired baseline: No direct Ethernet-to-Ethernet reference run recorded on this exact client.
  • Server CPU / interface telemetry during saturation load.
Next Discriminating Test: Connect the MacBook Pro via a USB-C Gigabit Ethernet adapter to the same FRITZ!Box LAN port and repeat the 60s TCP load test. If wired throughput is identical (~940 Mbps), the bottleneck is wired LAN, not Wi-Fi 6.
Finding 02 Distance/Obstacle Attenuation & Airtime Degradation

Observation: At position L2 (8.5m across 1 drywall partition), download throughput decreases by 39.4% to 492.4 Mbps. Average TCP retransmissions increase from 12 to 65.

Candidate Explanations

  • RF path loss and wall attenuation reduce SNR, triggering dynamic 802.11ax MCS rate fallback (from MCS 11 to MCS 7/8).
  • Lower PHY rates increase per-frame airtime consumption, leaving less available channel capacity.
  • Unobserved co-channel interference from neighboring 5 GHz BSSs in the adjacent room.

Missing Evidence

  • Continuous frame-level RSSI, noise floor, and negotiated MCS indices across the run.
  • Radiotap / monitor-mode capture distinguishing 802.11 MAC retries from end-to-end TCP retransmissions.
Next Discriminating Test: Log active MCS, NSS, and RSSI via macOS CoreWLAN / private framework during the test run, and repeat with laptop oriented 90 degrees to distinguish antenna polarization from room geometry.
Finding 03 Bufferbloat & Active Queue Latency Inflation

Observation: TCP saturation load inflates median RTT by +28.9 ms at L1 and +75.9 ms at L2. Latency promptly recovers within 5 seconds of load cessation.

Candidate Explanations

  • Excessive buffering in the AP's transmission queues or client TCP socket buffers (Bufferbloat).
  • 802.11 CSMA/CA contention delay: ICMP probes must contend for channel airtime with back-to-back TCP frames.
  • Downstream vs upstream queuing asymmetry (AP downlink aggregation vs client uplink scheduling).

Missing Evidence

  • Buffer occupancy / queue depth counters on FRITZ!OS.
  • One-way delay (OWD) decomposition to isolate uplink from downlink queueing.
Next Discriminating Test: Perform a UDP offered-load sweep (from 10% to 100% capacity in 10% increments) with small datagrams to identify the exact throughput inflection point where queueing delay begins to explode.
Finding 04 Failure Accounting & Experimental Validity

Observation: Detected 1 non-nominal run: 'L2_upload_rep3_20261015T120000Z' failed with outcome 'tool_error' (Reason: Simulated transient socket timeout during handshake).

Candidate Explanations

  • Transient TCP socket timeout or ARP resolution stall.
  • Client power-save mode or background OS process contention during handshake.

Missing Evidence

  • Kernel network log (`dmesg` / `log show --predicate 'process == "kernel"'`).
Next Discriminating Test: Retain the failed run in the dataset repository with outcome='tool_error'. Do not overwrite or discard; calculate condition statistics with explicit denominator N_valid / N_attempted.
